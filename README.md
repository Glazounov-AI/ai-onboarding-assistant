# AI Onboarding Assistant

Telegram-бот для обучения и первичной проверки знаний сотрудников. Проект объединяет учебные материалы, AI-наставника, тестирование и сохранение прогресса в PostgreSQL.

## Возможности

- Начало и возобновление обучения через Telegram.
- Работа с учебным материалом и AI-наставником на базе OpenAI API.
- Тестирование по банку вопросов с заданным проходным баллом.
- Повторная попытка тестирования, если она разрешена учебным профилем.
- Сохранение учебных сессий, попыток и ответов в PostgreSQL.
- Восстановление активного тестирования после перезапуска процесса бота.
- Защита от повторной обработки одного ответа в конкурентных запросах.
- Настройка учебного сценария через YAML-профиль.

## Технологии

Python, aiogram 3, OpenAI API, Pydantic / pydantic-settings, SQLAlchemy AsyncIO, asyncpg, PostgreSQL 16, Alembic, Docker Compose, pytest.

В Docker используется `python:3.13-slim`. Для локальной разработки использовался Python 3.14.

## Команды Telegram

| Команда | Назначение |
| --- | --- |
| `/start` | Начать или возобновить обучение |
| `/cancel` | Отменить текущее обучение |
| `/quiz` | Начать или продолжить тестирование |
| `/retry` | Повторить тестирование после неуспешной попытки, если повтор разрешён |

В демонстрационном сценарии пользователь проходит обучение, отвечает на вопросы и получает результат тестирования.

## Конфигурация

Создайте `.env` на основе `.env.example`:

```powershell
Copy-Item .env.example .env
```

Заполните значения `BOT_TOKEN`, `OPENAI_API_KEY` и `POSTGRES_PASSWORD`. Не публикуйте `.env` и секреты в Git.

Основные параметры:

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен Telegram-бота; обязателен |
| `OPENAI_API_KEY` | Ключ API AI-наставника; необходим при запуске |
| `OPENAI_MODEL` | Модель OpenAI; по умолчанию `gpt-4o-mini` |
| `OPENAI_BASE_URL` | Адрес совместимого API |
| `POSTGRES_DB` | Имя базы данных |
| `POSTGRES_USER` | Пользователь PostgreSQL |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL; обязателен |
| `POSTGRES_HOST` | Адрес PostgreSQL |
| `POSTGRES_PORT` | Порт PostgreSQL |
| `TRAINING_PROFILE` | Путь к YAML-профилю |
| `APP_ENV`, `LOG_LEVEL` | Среда и уровень логирования |

Пример `config/training.example.yaml` определяет профиль `demo-onboarding`, версию `1`, учебный материал `materials/demo.md`, банк вопросов `quizzes/demo.json`, **5 вопросов**, проходной балл **80%** и разрешённую повторную попытку.

## Запуск с Docker Compose

Команды выполняются из корня репозитория.

1. Подготовьте `.env` с действительными значениями.
2. Соберите образ и запустите PostgreSQL:

   ```powershell
   docker compose build bot
   docker compose up -d db
   docker compose ps
   ```

3. Примените миграции **до запуска бота**:

   ```powershell
   docker compose run --rm --no-deps --entrypoint python bot -m alembic upgrade head
   ```

   Команда использует `POSTGRES_HOST=db` и `POSTGRES_PORT=5432` внутри Docker-сети. Перед выполнением убедитесь, что контейнер PostgreSQL имеет статус `healthy`.

4. Запустите бота и проверьте логи:

   ```powershell
   docker compose up -d bot
   docker compose ps
   docker compose logs --tail=100 bot
   ```

Остановить сервисы без удаления тома базы данных:

```powershell
docker compose down
```

**Внимание:** `docker compose down -v` удаляет том PostgreSQL и сохранённые в нём данные. Не используйте эту команду без осознанного решения о потере данных.

PostgreSQL в текущем Compose опубликован на хосте только по адресу `127.0.0.1:5433`; внутри Docker-сети бот обращается к сервису `db:5432`.

## Локальный запуск на Windows

Для запуска бота вне Docker необходим работающий PostgreSQL, доступный с хостовой машины. В текущем Compose для этого используется `127.0.0.1:5433`.

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Если локально используется другая поддерживаемая версия Python, адаптируйте команду создания окружения.

В локальном `.env` укажите:

```dotenv
POSTGRES_HOST=127.0.0.1
POSTGRES_PORT=5433
```

Запустите базу, выполните миграции и запустите приложение:

```powershell
docker compose up -d db
python -m alembic upgrade head
python -m app
```

**Не запускайте одновременно локальный и контейнерный экземпляры бота с одним Telegram-токеном:** оба используют polling и будут конфликтовать при получении обновлений.

## Миграции и хранение данных

Миграции Alembic находятся в `migrations/`. Начальная ревизия — `3fb5efc5de8f`.

```powershell
python -m alembic current
python -m alembic heads
python -m alembic upgrade head
```

В PostgreSQL используются таблицы сотрудников, учебных сессий, попыток тестирования и ответов. Бот при старте проверяет подключение к базе (`SELECT 1`), **но не применяет миграции автоматически**.

В aiogram используется `MemoryStorage` для оперативного FSM-состояния; долговременные данные обучения и тестирования сохраняются отдельно в PostgreSQL. Поэтому наличие PostgreSQL не означает, что абсолютно всё FSM-состояние переживает перезапуск процесса.

## Банки вопросов и генерация

Профиль задаёт путь к банку вопросов (`quiz.bank_file`). Отдельный сервис `QuizGenerator` умеет обращаться к OpenAI API для формирования банка и проверяет структуру ответа, идентификатор и версию профиля, число вопросов и ссылки на исходный учебный материал.

Наличие этого сервиса **не означает**, что команда `/quiz` генерирует новый банк при каждом вызове. В текущем демонстрационном профиле используется файл `quizzes/demo.json`.

## Тестирование и проверки

Запуск тестов:

```powershell
python -m pytest
```

Проверка Ruff (если установлен в окружении разработки):

```powershell
python -m ruff check .
```

В ходе разработки ранее был получен результат **129 пройденных тестов**. После последних изменений Dockerfile и зависимостей необходимо повторить полный прогон перед итоговым коммитом.

Среди проверяемых сценариев: сохранение и восстановление прогресса, работа репозиториев, обработчики Telegram, повторные ответы и конкурентная отправка ответа на один вопрос.

## Ограничения текущей версии

- Демонстрационный профиль содержит один учебный сценарий; полноценная панель администрирования учебных программ не заявлена.
- Telegram-бот работает через polling, а не webhook.
- Оперативное FSM-состояние хранится в памяти процесса.
- Для работы AI-наставника требуется доступ к настроенному OpenAI-совместимому API.
- Миграции базы данных выполняются отдельной командой перед запуском приложения.

## Статус

Учебный проект с проверенными сценариями Telegram, PostgreSQL и Docker Compose. Перед публикацией окончательной версии предусмотрены финальные проверки тестов и линтера.
